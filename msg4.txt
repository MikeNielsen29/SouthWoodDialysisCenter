feat(docs): standalone printable HTML for the three client documents

The markdown files existed but were useless to a client: they had no VS
Code, and "open in browser" on a .md just shows plain text. The three
documents are the actual deliverable, so they need a form a client can
open and print.

scripts/build-client-docs.mjs
- Markdown -> self-contained HTML. No new dependency: marked /
  react-markdown would be a runtime cost for three static documents.
- Handles headings, nested lists, ordered lists, tables, blockquotes,
  code fences, hr, and inline bold/italic/code/links.
- Code spans are protected before bold/italic runs, otherwise a literal
  ** inside `code` becomes a <b>.
- Nesting is built with an indent stack, not string slicing, so parent /
  child relationships survive (verified with a synthetic 3-level case).

Print CSS is the point of the exercise:
- A4 with 16mm margins, print-color-adjust: exact so the warning boxes
  keep their colour in the PDF.
- break-inside: avoid on tables/rows/list items and thead as a repeating
  header group, so a table does not split with two orphan rows on the
  next page.
- The on-screen toolbar is hidden in print.

Output is standalone on purpose: a client can double-click it or receive
it by email and it renders correctly with no server and no internet.
External CSS or web fonts would break that.

package.json: npm run build:docs

Verified: element counts in the generated HTML match the markdown sources
across all three documents; nested and ordered nesting render correctly;
importing the module no longer rewrites files (import.meta.url guard).
