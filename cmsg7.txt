fix(seo,a11y): every page was shipping "{Page Title}" as its title

Two production bugs, both found by finally reading the rendered HTML
instead of the source — which is a thing my QA script had never done.

**1. The title template was a literal string.** Next.js substitutes a child
page's title into `title.template` by replacing the token `%s`. The
Content DB stores `"{Page Title} | {Brand}"`, which is a convention for
humans editing that field — Next does not understand it. So the template
passed through untouched and every page carrying its own title rendered:

    /listings → <title>{Page Title} | Prime Estates Realty</title>
    /contact  → <title>{Page Title} | Prime Estates Realty</title>

into the `<title>`, the OpenGraph title and the Twitter title. The
homepage looked right because it uses `title.default`, never the
template — which is exactly why this survived a QA pass that checked
layout, overflow and tap targets. A crawler was being told every page
had the same name.

`buildTitleTemplate()` now translates the human token, so a client editing
`titlePattern` in the admin keeps writing `{Page Title}` and never has to
learn `%s`. It lives in `lib/seo/title.ts` rather than in `app/layout.tsx`
because importing the layout from a test drags in the store layer and
`server-only`, which only resolves inside Next's bundler — a pure string
function that cannot be tested is one that ships broken.

The test for it immediately caught a second gap: the regex did not match
`{ PAGE TITLE }` with spaces inside the braces, which a client typing
into an admin field could easily produce, and which would have
reintroduced the same leak.

**2. `/contact` had no `<h1>`.** `SectionHeading`'s `as` prop accepted only
`"h2" | "h3"`, so a page whose only heading is a `SectionHeading` could
not emit one at all. Fixed at the component — the prop now accepts `h1`,
so the next page cannot repeat the mistake by accident.

`scripts/qa-audit.mjs` now checks `<title>`, `og:title`, `<h1>` count and
meta description on every page of every run, and fails loudly on a leaked
template placeholder. Both bugs were invisible to layout checks; the next
one should not be.

Verified: tsc 0 errors · 101/101 unit tests · audit script parses.
